# TestDB — legacy-админка + лендинг

Тестовое задание: модернизация legacy-проекта (Apache + PHP, MySQL). Проект поднимается
в Docker, содержит админку на jqGrid, справочники недвижимости и публичный лендинг.

## Запуск

Требуется Docker с Compose (Docker Desktop / Docker Engine).
Команды ниже — для Bash (Linux, macOS или WSL). Python и PHP на компьютере не нужны.

```bash
# Новый запуск: PHP в одноразовом контейнере генерирует локальные секреты
docker run --rm --user "$(id -u):$(id -g)" \
  -v "$PWD:/app" -w /app php:8.2-cli php scripts/setup-secrets.php
docker compose up -d --build
docker compose exec -T web php scripts/set-admin-password.php < .local-secrets/admin-password
```

Если PHP уже установлен локально, вместо первой команды можно выполнить
`php scripts/setup-secrets.php`. Генератор работает до запуска Compose и не
требует подключения к БД или установки Composer-зависимостей.

При первом старте база инициализируется из `sql/testdb.sql` (уже содержит все изменения),
а PHP-зависимости ставятся автоматически (`composer install` при старте контейнера).

- Лендинг: <http://localhost:8080/>
- Админка: <http://localhost:8080/admin/>

### Учётные данные админки

Логин: `admin`. Случайный пароль хранится только в локальном файле
`.local-secrets/admin-password` (права 0600). Для просмотра:

```bash
cat .local-secrets/admin-password
```

`.env` содержит случайные пароли MySQL. Оба локальных пути
исключены из Git и запрещены для HTTP-доступа. Не публикуйте их и не отправляйте
вывод `docker compose config`: он может содержать подставленные секреты.

Публичный дамп содержит admin с пустым шифротекстом: до выполнения команды
`set-admin-password.php` вход невозможен. Веб-порт доступен только на `127.0.0.1`.

Пароли пользователей хранятся как `AES_ENCRYPT(password_hash(пароль), AESKEY)`.
Ключ `AESKEY` задан в `php/config.php` (по условию задания) и может быть
переопределён необязательной переменной `AES_KEY` в `.env`. Ключ не секретен:
при его утечке вместе с дампом расшифровывается только bcrypt-хеш, а не пароль.
Записи старого формата (`AES_ENCRYPT` от самого пароля) принимаются при входе
и сразу перезаписываются в новом формате.

Генератор предназначен для новой установки и отказывается заменять существующую
конфигурацию. Для существующей БД изменение `.env` само по себе не меняет пароли
MySQL. Смена ключа AES делает существующие записи паролей нерасшифровываемыми:
после неё пароли нужно задать заново (`set-admin-password.php` для admin).

## Состав

- `index.php` + `templates/` — публичный лендинг (Smarty 5); описания квартир рендерятся
  из Quill Delta через `nadar/quill-delta-parser`.
- `admin/` — административная панель: квартиры (`NL_PROP_RESALE`) и справочники
  «Вид из окна», «Материал дома», «Тип дома», пользователи.
- `php/` — конфигурация и общие функции работы с БД.
- `sql/testdb.sql` — итоговый дамп базы; `sql/migrations/` — пошаговые изменения схемы.
- `docker/`, `docker-compose.yml` — окружение (PHP 8.2 + Apache, MySQL 8.0).
- `tests/`, `run-tests.sh` — интеграционные тесты PHPUnit на отдельном стенде.

## Разработка

```bash
docker compose exec web bash
docker compose exec db mysql -uroot -p testdb  # ввести локальный DB_ROOT_PASSWORD
```

## Тесты

Нужен Docker. На компьютере PHP не нужен. Прогон не трогает уже запущенный стек
на портах 8080 и 33066: скрипт копирует проект во временный каталог, поднимает
отдельный compose-проект `testii_test` (веб **8090**, MySQL **33076**), ставит
PHPUnit, задаёт пароль admin и после тестов удаляет и стенд, и копию.

```bash
./run-tests.sh
# то же самое
make test
```

Если эти порты заняты:

```bash
TEST_WEB_PORT=8091 TEST_DB_PORT=33077 ./run-tests.sh
```

Входные данные:

- дома, материалы, квартиры и пользователь `admin` — из `sql/testdb.sql`;
- пароль `admin` скрипт генерирует заново во временной копии (в git его нет);
- агент `test_agent` и гость `test_guest` создаются в `tests/bootstrap.php`;
- описания Quill и JPEG для загрузки тесты собирают сами и после проверки удаляют.
